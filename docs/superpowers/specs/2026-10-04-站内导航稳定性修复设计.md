# 站内导航稳定性修复设计

## 问题

网站使用 `HashRouter` 和 React `Link`／`NavLink` 完成站内切换。在 Edge 和 Codex 内置浏览器中，点击任意站内导航后，URL 会变为正确的 `/#/...` 地址，但 React 根节点内容被清空，页面持续空白；手动刷新后，对应页面可以正常显示。深色模式等非路由状态更新正常，因此问题限定在客户端路由切换链路，而不是页面数据、样式、域名或 GitHub Pages 部署。

## 目标

- 所有站内导航第一次点击就能打开目标页面，不再依赖手动刷新。
- 保留现有 `/#/book`、`/#/tip/01-01` 等 URL，避免破坏已经分享的链接。
- 保留 GitHub Pages、纯静态部署和现有本地功能。
- 页面重新加载时不出现突兀白屏。

## 方案

### 统一站内链接

新增一个统一的站内链接组件，替代项目中的 React `Link` 和 `NavLink`。组件仍输出可访问的 `<a>` 元素，并保留正确的 `href`。

普通左键点击时，组件执行以下流程：

1. 阻止 React Router 的客户端跳转。
2. 使用浏览器 History API 把当前地址更新为目标 Hash 路由。
3. 立即执行整页重新加载。
4. 页面启动后，现有 `HashRouter` 根据 Hash 渲染目标页面。

浏览器后退或前进时，监听 `popstate` 并重新加载当前历史地址，避免恢复先前保留的单页应用状态后再次走入故障的客户端路由切换。

按住 Ctrl、Shift、Alt、Command，使用中键，或设置非 `_self` 目标时不拦截，继续使用浏览器原生行为，以支持新标签页打开。

### 当前导航状态

统一链接组件读取当前路由，为顶部导航和手机底部导航保留现有的 `active` 样式。普通正文链接不增加额外状态。

### 加载过渡

在 `index.html` 的 React 根节点中放置轻量级初始占位内容，并使用内联样式设置与网站一致的米白底色、绿色标识和“正在打开”提示。React 成功启动后会替换该占位内容。

这样即使重新执行前端脚本需要短暂时间，用户看到的也是同风格过渡，而不是白屏。若脚本真的加载失败，占位内容仍会保留，避免完全空白。

## 修改范围

- 新增统一站内链接组件。
- 替换首页、顶部导航、手机导航、章节入口、建议详情、上一条／下一条、页脚和空状态中的站内链接。
- 为入口 HTML 添加加载占位和最少的内联样式。
- 不修改外部链接、PDF 链接、深色模式、筛选、收藏、待做和已完成功能。
- 不修改域名、DNS、GitHub Pages 设置和内容数据。

## 验证

1. 执行 TypeScript 检查和生产构建。
2. 从首页依次打开全书、章节、建议详情、术语表、清单和版本说明。
3. 测试顶部导航、手机导航、页脚和上一条／下一条。
4. 确认每次点击第一次就显示，不需要手动刷新。
5. 确认深色模式、筛选和本地收藏仍然正常。
6. 确认直接访问和刷新 `/#/...` 地址仍然正常。
7. 确认浏览器后退和前进均显示对应页面，不需要手动刷新。

## 验收标准

- Edge 和 Codex 内置浏览器中，所有站内链接首次点击即可显示目标页面。
- 页面切换只出现短暂的同色加载过渡，不出现持续空白。
- URL、外部链接、PDF 和 localStorage 功能保持兼容。
- 浏览器后退和前进第一次操作就显示正确页面。
